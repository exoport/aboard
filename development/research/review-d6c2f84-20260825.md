# aboard — final review at d6c2f84

## Verdict

Sound to build on. The build is clean (`go build`, `go vet`, `go test -race -count=3`, `make lint`, `xcompile-windows`, `docs-check`, 101/101 smoke), and the three properties the project sells — the four server-enforced tab guarantees, the self-describing manifest, and a CLI tree that mounts inside another binary with no ceremony — each held up under direct probing, not just reading. Two real defects sit under that, both in `server.go`, both narrow-window races, both a few lines to fix: the state write path has no mutual exclusion, so concurrent writes both return 200 and one is destroyed silently; and the SSE fanout sends on a channel the reader closes, which killed the process outright under a reproduced disconnect race. Everything else is medium or below, and much of the medium tier is documentation and test coverage rather than behaviour. The real state: a well-built system whose concurrency story was never written down, and whose suite — genuinely strong on layout, recipes, init and command parity — has an asymmetric blind spot. Nothing concurrent is tested, five of six `writeWarnings` detectors can be deleted with the suite green, and three browser-suite assertions cannot fail against the fixture they ship with. Fix the two highs, then close the coverage gaps plan-1 §13 already asked for.

## High

**Unserialised read-check-write in `postState`** — `pkg/aboard/server.go:568` — the read → CAS → reconcile → write span holds no lock (`s.mu` guards only fanout), so two overlapping POSTs both pass CAS and both write; 40/40 barrier-synchronised trials returned (200, 200) with one edit gone from disk, and the journal records the lost write as if it landed. — Hold a dedicated `sync.Mutex` from `os.ReadFile` (:568) through `writeAtomic` (:626); test N concurrent posts off one base for exactly one 200. — fixed: the span moved into `commitState`, held under a dedicated `s.writeMu` from the read through `writeAtomic` and the journal append, with notification left outside it; `TestConcurrentPostsProduceExactlyOneWinner` posts 12 documents off one base through a barrier and asserts one 200, eleven 409s, the winner's document on disk and exactly one journal entry (12 of 12 returned 200 before the fix). `TestTheStateFileHasOneWriter` keeps the audit honest: one caller of `writeAtomic`, one rename onto the state file, and no `os.WriteFile`/`os.Create`/`os.OpenFile` on it anywhere in the package.

**`fanout` sends on a channel `events` closes** — `pkg/aboard/server.go:775` — channels are copied under `s.mu`, the lock released, then sent to; a client disconnecting in that window is closed first and the send panics. Reproduced fatally — `watch()` is a bare goroutine with no recover, the process died, `aboard status` reported a stale record. `notifyWatchers` (`journal.go:282`) is the same shape. — Delete from the map without closing (nothing else reads it), or hold `s.mu` across the non-blocking sends; add `recover()` to `watch`/`watchUI`. — fixed: `fanout` and `notifyWatchers` now send under `s.mu` rather than to a copy taken before releasing it (chosen over delete-without-close, which would have left "never close a subscriber channel" as an unenforced invariant across two files); `watch` and `watchUI` run through `server.guard`, which recovers and logs through `Options.Logger`. `TestFanoutSurvivesAClientDisconnecting` and `TestNotifyWatchersSurvivesAWatcherDisconnecting` reproduced both the data race and `panic: send on closed channel` on the unfixed code and pass at `-race -count=20`, and `TestEveryServerGoroutineRunsUnderGuard` asserts the two launches actually go through `guard` — reverting them to a bare `go srv.watch()` left the rest of the suite green.

## What is sound

Exercised, not merely read. **The four guarantees**: a dropped tab returns as a `pendingRemoval` and `reconcileNextID` scans *both* documents so a restored tab's ids still raise the counter; an omitted `touched` carries forward verbatim over HTTP; `carryAcks`/`restoreAcks` walk shape-tolerantly; a missing `__by` yields `actorUnknown` with agent powers only, and `apply` refuses `--by human`. **Containment where it counts**: loopback-only bind confirmed with `ss`; the html-tab CSP byte-identical for a tab and a stack block, `connect-src 'none'` intact, `sandbox="allow-scripts"` without `allow-same-origin`; uploads sniffed from magic bytes with the server choosing the filename and SVG excluded; every body-reading route capped; base-path stripping resistant to `..`, `%2f` and `--path-as-is`; static serving allow-listed; mermaid at `securityLevel: 'strict'` and no view putting untrusted text through `innerHTML`. **Embeddability**: a mock ape host mounted `cli.NewRootCmd` and ran `--help`, `status`, `version` and `serve` with zero ceremony; `Options.Stdin/Stdout/Stderr` honoured by every client command; `signal.NotifyContext` confined to `Execute`, so mounting steals no signals. **Layout**: `--cwd p1`, `--cwd p1/` and a subdirectory run all resolve to one root and one port; a *file* named `.aboard` is not a root; Init's five nesting rules behave as documented; port derivation pinned to exact vectors rather than a range; `init --example` recomputes `nextId` instead of copying it. **Recipes**: four-tier precedence with the winner naming every file it shadows, frontmatter tolerances (BOM, CRLF, padded delimiter) with matching negatives, invalid files reported with the reason rather than skipped, template extraction past a decoy ```json fence, index determinism — and the built-ins are live, four applied against a running board. **The manifest at the top level**: `capsHash` drift is CI-gated through the stamped controls module (verified by deliberately drifting a spec), `gen-docs --out -` reproduces `docs/reference/cli.md` byte-identically, and `make caps` is idempotent with a load-bearing double build. **The browser**: every URL goes through `api()`, `--base-path /brd` verified live end to end including uploads and the html-tab route, the `aboard.*` bridge rename complete, TYPES/MODULES/specs 15/15/15 with all 15 mounting headlessly at zero window errors and 131 declared controls. **Release plumbing**: `.bingo` pins match ape's, goreleaser-action pinned to the bingo pin (stricter than ape), the cosign identity regexp anchored and escaped, `GOOS=windows` vet/build/test-compile clean, NOTICE's mermaid version and sha256 both reproducing.

## What this review could not verify locally

The DNS-rebinding chain itself needs attacker DNS and a browser — only Host-acceptance and the `/health` disclosure were demonstrated, and the derived-port range (41000–48999) makes it harder than a fixed-port dev server. The embedded-host version and invocation-string defects are latent: ape has no dependency on this module yet, so nobody can hit them today. Cross-uid consequences of the 0600 mode change were reasoned about, not reproduced. Windows is covered only by cross-compilation and test compilation, never by running the suite there. Nothing was tested behind a real reverse proxy, so `--base-path` is proven against curl and Chromium but not nginx or the VS Code webview in anger. And both high findings needed deliberate pressure to reproduce — barrier synchronisation for the write race, 350 SSE clients timed against the watcher's 200 ms poll for the panic — so neither shows up in casual single-session use, which is exactly why they survived this long.
